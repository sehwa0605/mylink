# mylink 제품 기획서 (PRD, Product Requirements Document)

## 1. 프로젝트 개요
- **한 줄 정의:** 내 프로필과 다양한 활동 링크를 한 페이지에 모아 공유하는 링크인바이오(Link-in-bio) 서비스
- **목표:** '아이디어를 현실로: 바이브코딩' 수업 과제 및 개인 포트폴리오용 웹 애플리케이션 완성
- **구현 전제:**
  - 프레임워크: Next.js 16.3.4 (App Router, Webpack 모드)
  - 인증 및 데이터베이스: Firebase Authentication (Google 소셜 로그인) + Cloud Firestore
  - 상태 관리 및 캐싱: TanStack Query v5 (갱신형 데이터 페칭, 실시간 onSnapshot 없음) + Zustand v5
  - 스타일링: Tailwind CSS v4 + shadcn/ui (토큰 기반 스위치 네온 디자인)

---

## 2. 대상 사용자
1. **페이지 소유자 (로그인 사용자):**
   - 자신의 구글 계정으로 로그인하여 프로필(이름, 소개글)을 수정하고 링크를 추가/수정/삭제함
   - 내 페이지 방문자들의 링크 클릭 통계를 확인하고 공유함
2. **방문자 (비로그인 사용자):**
   - 공유받은 주소(`/{displayName}`)로 접속하여 프로필과 등록된 링크를 열람하고 클릭함

---

## 3. 사용자 시나리오
1. **방문자 시나리오:**
   - `/{displayName}` 주소로 접속 → 소유자의 프로필(사진, 이름, 소개)과 링크 목록 확인 → 원하는 링크를 클릭하여 새 탭으로 이동 (동시에 클릭 수 +1 집계)
2. **소유자 시나리오:**
   - 메인 화면(`/`) 접속 → Google 계정으로 로그인 → 마이페이지에서 프로필(이름, 한 줄 소개) 수정 → 링크 추가/수정/삭제 → 상단 [내 페이지]를 눌러 공개 화면 확인 → [통계] 탭에서 총 클릭 수와 링크별 순위 확인
3. **예외 시나리오:**
   - 가입되지 않거나 존재하지 않는 주소(`/{존재하지않는아이디}`)로 접근 시 서버 컴포넌트에서 404 상태 코드 반환 및 스위치 콘솔 스타일 404 페이지 노출

## 4. 화면(라우트) 목록
| 주소 | 화면명 | 설명 | 로그인 필요 여부 |
|---|---|---|---|
| `/` | 홈 / 랜딩 | 비로그인 시 서비스 소개 랜딩 페이지, 로그인 시 마이페이지 본문 노출 | 선택 |
| `/mypage` | 마이페이지 | 프로필 수정, 링크 인라인 추가 폼, 내 링크 목록 및 클릭 수 관리 | 필수 (비로그인 시 안내 화면) |
| `/dashboard` | 대시보드 | 내 링크 카드, [링크 추가] 모달 다이얼로그, 링크 수정/삭제 | 필수 (비로그인 시 안내 화면) |
| `/stats` | 통계 | 총 클릭수 요약 카드, 링크별 가로 막대 차트, 클릭 순위표 | 필수 (비로그인 시 `/` 리다이렉트) |
| `/[displayName]` | 공개 프로필 | 외부 공유용 퍼블릭 페이지. 보기 전용, 클릭 수 숨김, 클릭 시 카운트 증가 | 불필요 (누구나 접근 가능) |
| `/[displayName]` (없는 주소) | 404 Not Found | 사용자를 찾을 수 없을 때 안내하는 콘솔 스타일 404 페이지 | 불필요 |

## 5. 기능 요구사항

### 5-1. 링크 관리
- **입력 검사 (`validateLink`):**
  - 제목: 필수, 앞뒤 공백 제거 후 1~100자
  - URL: 필수, 공백 불가, `http://` 또는 `https://` 자동 보정, `mailto:` 형식 지원
  - 도메인 검사: 최상위 도메인(TLD) 2자 이상 검사 (`example.c`, 숫자 IP 형태 등 거절)
- **아이콘 자동 매핑 (`linkIcon`):**
  - URL 패턴 분석: GitHub, YouTube, Instagram, X(Twitter), velog, 메일(`mailto:`), 블로그 등 판별
  - 브랜드 로고는 Simple Icons 공식 색상 적용, 일반 사이트는 Google Favicon API 활용 (실패 시 Lucide 폴백)

### 5-2. 프로필 관리
- **구글 로그인:** Firebase Auth를 사용하며, 공개 주소 핸들(`displayName`)은 구글 이메일의 `@` 앞부분으로 고정
- **프로필 수정:**
  - 이름(실명, 필수, 최대 30자)과 한 줄 소개(선택, 최대 60자)를 `users/{uid}` 및 `users/{uid}/profile/main`에 `writeBatch`로 동시 저장
  - 낙관적 업데이트(Optimistic Update) 적용으로 저장 버튼 클릭 시 즉시 화면 반영

### 5-3. 클릭 수 및 통계
- 공개 페이지에서 링크 클릭 시 Firestore `increment(1)`을 통해 서버에서 원자적으로 카운트 증가 (새 탭 열림 차단 없음)
- 공개 페이지에서는 방문자에게 클릭 수를 숨기고, 로그인한 본인의 마이페이지/대시보드/통계 화면에서만 표시

## 6. 데이터 모델 (Firestore)
```
users/{uid}                         ← 사용자 문서
│   uid          string             Firebase 고유 계정 번호
│   displayName  string             이메일 @ 앞자리 (공개 주소 핸들, 생성 후 변경 불가)
│   username     string|null        구글 계정 실명 / 프로필 이름
│   email        string|null        구글 이메일
│   photoURL     string|null        구글 프로필 사진
│   bio          string             한 줄 소개
│
├── profile/main                    ← 프로필 수정 히스토리/배치 저장본
│       name       string           수정된 이름
│       bio        string           수정된 한 줄 소개
│       updatedAt  timestamp        수정 시각 (serverTimestamp)
│
└── links/{linkId}                  ← 링크 서브컬렉션
        title       string          링크 제목 (1~100자)
        url         string          정규화된 URL
        createdAt   timestamp       생성 시각 (정렬 기준)
        updatedAt   timestamp       수정 시각
        clickCount  number          누적 클릭 횟수 (기본값 0)
```

## 8. 범위 밖 (Out of Scope)
다음 기능들은 프로젝트의 단순성과 안정성을 위해 개발 범위에서 제외합니다:
- 자체 이메일/비밀번호 회원가입 (구글 소셜 로그인만 지원)
- 직접 사진 파일 업로드 (구글 프로필 사진 자동 연동)
- 링크 드래그 앤 드롭 순서 변경 (생성 역순 정렬 유지)
- 실시간 리스너(`onSnapshot`)를 통한 타인 화면 즉시 동기화
- `displayName`(공개 주소 아이디) 변경 기능 (중복 검사 및 무결성 이슈 방지)
- 결제 및 다중 권한 관리자 기능
